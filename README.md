# げんつきマップ / gentuki

**https://seimei777.github.io/gentuki/**

原付一種（50cc以下・白ナンバー）で走るときに「ここ二段階右折？」「この道、原付入れる？」を
**走る前に**確認できる地図。神戸市・西宮市・宝塚市に限定。

- データ元：**兵庫県警の交通規制情報オープンデータ**（JARTIC 経由・2026年7月版）＋ OpenStreetMap
- 地図描画：MapLibre GL JS ＋ 地理院タイル（淡色）
- ライセンス：コードは MIT、データは各出典の条件に従う（下記）

## 1. 背景 / 解こうとしている問題

原付一種の二段階右折は、次のどちらかで**義務**になる。

1. 交差点の手前に「原動機付自転車の右折方法（二段階）」の**青い標識**がある（車線数に関係なく義務）
2. **車両通行帯が3以上**の道路の交差点で、**信号機または警察官の交通整理がある**とき

逆に「原動機付自転車の右折方法（小回り）」の標識がある交差点では、3車線以上でも
**二段階右折してはいけない**（右折レーンから普通に曲がる）。
違反すると交差点右左折方法違反で **反則金3,000円・1点**。

問題は「その交差点が3車線以上かどうかを、走りながら判断しないといけない」こと。
標識は交差点直前にしかなく、初見の道では手遅れになりやすい。実際に困る人が多い。

### 先行事例との差分＝このプロジェクトの存在理由

[交通規制情報オープンデータマップ](http://hotmist.ddo.jp/jartic_kisei/) は、同じJARTICデータを全国・73種別で可視化した個人プロジェクトで、
種別55（二段階右折）と56（小回り）も含んでいる。**つまり「規制データを地図に出す」こと自体は既に先行者がいる。**

決定的な差はここにある。

> **兵庫県全域で、種別55（二段階右折の標識）はわずか 5 件。**
> 一方、実際に二段階右折が義務になる交差点は、本プロジェクトの推定で 608 件（対象7市のみ）。

標識データをそのまま出すだけでは、**二段階右折が必要な地点の95%以上が地図に現れない。**
法令上の義務は「車両通行帯3以上＋信号機あり」で発生するのに、標識は例外的にしか立っていないからだ。
この欠落を、車両通行帯数と信号機の突き合わせで埋めるのが本プロジェクトの中身であり、
商用のナビタイムも、先行の個人マップも、この推定ロジックは公開していない。

ナビタイムも公式に「国や地方公共団体が整備した全国の交通規制情報データを活用」と明言しており、
**元データは我々が使うのと同じもの**。差が付くのは加工の部分だけ。

### 台湾という先行市場

台湾には「禁行機車」（機車進入禁止）と「兩段式左轉」（＝日本の二段階右折と同型）があり、
これを回避するナビは既に商用化されている（導航王など）。
一方、現地メディアによれば **Googleマップの機車導航は禁行機車・二段式左轉に完全対応していない**とされ、
「事前にルートを目視確認せよ」と注意喚起されている。
巨大プラットフォームが車種別のローカル規制を取りこぼし、ローカル専業がそこを埋める構図が
10年規模で成立している市場が、すぐ隣にある。

## 3. データ調査（ここが本丸）

### 3.1 交通規制情報オープンデータ（JARTIC）

- 提供：公益財団法人 日本道路交通情報センター（JARTIC）
- 中身：各都道府県警の交通規制データベースを「拡張版標準フォーマット Ver k_2.1」に変換したCSV
- 単位：都道府県警ごとに1ファイル（例：`兵庫県警_202607_k_2.1.csv`、約100MB・CP932）
- 更新：毎月月初。**更新されると前月分は取得できなくなる**（アーカイブは自前で持つ必要あり）
- 入口：https://www.jartic.or.jp/service/opendata/ （利用規約の確認が必要）
- 実データの場所：`/d/opendata/opendata.json` に当月分のzipリンク一覧が入っている

**兵庫県警データの実測（2026年7月版・全県 116,939件）**

| 共通規制種別コード | 名称 | 件数 |
|---|---|---|
| 55 | 一般原動機付自転車の右折方法（**二段階**） | 5 |
| 56 | 一般原動機付自転車の右折方法（**小回り**） | 649 |
| 58 | 車両通行帯（交差点）※`車両通行帯数`を持つ | 4,632 |
| 98 | 信号機 | 7,224 |
| 5 / 7 | 各種通行止め（対象車両コード付き） | 約1,900 |
| 11 | 一方通行 | 5,268 |

**つまり「二段階右折の判定に必要な3要素（標識・車線数・信号）が全部この1ファイルに入っている」。**
これが今回の一番大きい発見。

### 3.2 対象車両コードの読み方

`対象車両コード1_A〜D` は**桁が立っているビット列**。右から数えてn桁目が1なら該当。

- カテゴリA：1=車両（自動車＋原付＋軽車両）、2=自動車、…
- カテゴリD：1=二輪（自動二輪＋原付）、2=自二輪、3=自転車、**4=原付（一般原動機付自転車）**、
  5=小二輪、6=軽車両、10=特定原付、11=特例特定原付

したがって **原付一種が禁止されるのは `A のビット1`／`D のビット1`／`D のビット4` のいずれか**。
（例：「二輪の自動車・一般原動機付自転車通行止め」は `D=1010` ＝ 自二輪＋原付）
`除外車両コード` 側に原付が立っている場合は除外＝走れる、も見る必要がある。

### 3.3 二段階右折の判定ロジック（本アプリの実装）

```
確定（標識ベース）
  ├ 種別55 → 二段階右折 義務（標識あり）
  └ 種別56 → 二段階右折 禁止（小回り指定）

推定（法令の原則から計算）
  種別58 の 車両通行帯数 ≧ 3
    かつ 進入路端点から 80m 以内に 種別98（信号機）
      → その方向から右折するとき二段階右折
    ＋ 45m以内に 種別56 があれば「近くに小回り標識あり」フラグを立てる（現地標識が優先）
```

`片側・両側コード` は種別58では全件「片側」だったため、`車両通行帯数` はそのまま**片側の車線数**として扱える
（両側登録なら両方向合計になるので要注意）。

### 3.4 精度の検証

推定した地点の最寄り幹線道路をOpenStreetMapで突き合わせたところ、
**国道2号・山手幹線・国道43号・国道28号・浜手幹線・湊町線・みなと空港線**など、
実際に片側3車線以上ある神戸の主要幹線に集中した（中心部サンプルで40m以内に幹線道路が無いものは7件のみ）。
ロジックは妥当と判断している。

ただし以下は**未解決の誤差要因**として明示する：

- `車両通行帯数` が交差点手前の実際の進入車線数と一致しない可能性
- 信号機レコードが交差点単位か信号柱単位か不明（80m のしきい値は経験的）
- 小回り標識が交差点の一部の進入路だけに立っている場合、45m のバッファが他の進入路にかかる
  → **除外せずフラグ表示に留めた**（「二段階不要」と誤って断言する方が危険なため）

### 3.5 原付が入れない道路

公安委員会規制（上記データから抽出）に加えて、**道路法上の自動車専用道路は規制データに入らない**ため
OpenStreetMap の `highway=motorway` / `moped=no` から補完した。

3市内で原付一種が入れない主なもの：

- 阪神高速（3号神戸線・5号湾岸線・7号北神戸線・31号神戸山手線・**32号新神戸トンネル**）
- 第二神明道路、中国自動車道、新名神高速道路、山陽自動車道、神戸淡路鳴門自動車道
- **山麓バイパス（全区間）**、**六甲北有料道路（全区間）**、**六甲有料道路の六甲山トンネル区間**
  （神戸市道路公社：50cc以下および125cc以下かつ4.0kW以下は通行禁止。ミニカーは可）
- **芦有ドライブウェイ**（125cc以下は通行禁止、土日祝は二輪車全般が通行禁止）
- 六甲山系の一部道路（**土日祝のみ二輪通行止め**の区間が多数）← 規制データに時間条件付きで入っている

### 3.6 使わなかった／使えなかったもの

- **Google Maps Platform**：地図コンテンツのスクレイピング・事前取得・保存が規約で禁止。
  自前データを重ねる分には問題ないが、タイルやジオコード結果を溜める設計にはできない。
- **国土数値情報の行政区域**：今回は Linked Open Addresses Japan (uedayou.net) の市区町村 GeoJSON で代用。

## 5. UI/UX 設計（既存ナビアプリの調査から）

参考にした挙動：

- ツーリングサポーターは「およそ500m先、右方向、二段階右折禁止地点です」と**距離＋方向＋種別**で読み上げる
  → 手前で分かることに価値がある。地図を見せるだけでは走行中に使えない
- 京都の有志マップは**色分けの語彙**が良い（二段階／小回り／二段階だが待避場所なし）
  → 「待避スペースの有無」は現地でしか分からない情報なので、ユーザー報告で足す余地がある

本アプリの方針：

1. **走る前に見るモード**が主、走行中は音声のみ。地図の操作を前提にしない
   （走行中のスマホ操作は道交法違反。アプリ内に明示する）
2. **色は3つだけ**：オレンジ＝二段階右折（推定）／青＝小回り（禁止）／赤＝原付進入禁止
3. **確定と推定を必ず見分けられるようにする**。推定は塗りつぶさず輪郭で描く
4. 近づいたら**画面を占有する大きいカード**＋バイブ＋読み上げ。地図に戻す操作を要求しない
5. 夜間走行前提のダークテーマ
6. 出典・更新年月・免責を1タップで出せる位置に置く（規制は変わる。標識が正）

## 6.5 ルート探索

| 役割 | 使うもの | 理由 |
|---|---|---|
| 経路探索 | **Valhalla**（FOSSGIS公開インスタンス）`costing: motor_scooter` | 原付相当のプロファイルが標準で存在する。実測で `auto` は山麓バイパス＋新神戸トンネル（どちらも原付禁止）を通るルートを返すのに対し、`motor_scooter` は国道428号へ迂回した |
| 地点検索 | 国土地理院 住所検索API ＋ Nominatim | 前者が日本の住所・地名に強く、後者が店名・POIを拾う。両方投げて統合し、クエリとの一致度と3市の内外で並べ替える |
| 背景地図 | 地理院タイル 淡色 | 出典表示のみで利用可 |

すべて CORS が開いているので、静的サイトのまま動く（サーバ不要）。

### ルート解析でやっていること

1. Valhalla の maneuver から**右折（type 9/10/11）だけ**を抜く
2. その地点の55m以内に二段階右折ポイントがあれば「この右折は二段階」と判定 → 手順リストで強調し、音声で読み上げる
3. 「二段階右折をできるだけ避ける」を入れると、該当交差点を `exclude_locations` に入れて再計算し、二段階が減っていれば差し替える
4. ルートの座標列と原付通行禁止区間の**線分距離**を取り、12m以内の点が5個以上続いたら重なりと判定（並行する別の道を拾わないため。出発・到着の前後120mはスナップ誤差が出るので除外）
5. 重なったものが**時間・曜日限定の規制**なら強く警告する。経路探索はこの規制を知らないため、ここが唯一の盲点になる（六甲山系の土日祝の二輪通行止めなど）
